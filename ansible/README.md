# Ansible — configuration layer

Takes a bare Ubuntu 22.04/24.04 host to a running Gitea stack. Replaces
`scripts/bootstrap.sh` and `scripts/harden.sh` with idempotent roles; the shell
scripts remain in `scripts/` for anyone who would rather not install Ansible.

```bash
ansible-galaxy collection install -r requirements.yml
ansible-playbook site.yml
```

The inventory is generated by Terraform. To run against a host Terraform does not
manage, copy `inventory/hosts.ini.example` to `inventory/hosts.ini`.

## Roles

| Role | Replaces | Does |
|---|---|---|
| `common` | part of `bootstrap.sh` | base packages, unattended security upgrades |
| `hardening` | `harden.sh` | UFW, fail2ban, sshd, sysctl |
| `docker` | part of `bootstrap.sh` | Docker Engine + Compose plugin from the official repo |
| `nginx_tls` | part of `bootstrap.sh` | nginx vhost, Let's Encrypt, bare-IP fallback |
| `gitea_stack` | `deploy.sh` | ships the compose stack and `.env`, waits for health |
| `backups` | cron equivalent | systemd timer running `scripts/backup.sh` nightly |

## Tags

```bash
ansible-playbook site.yml --tags hardening   # re-apply security config only
ansible-playbook site.yml --tags deploy      # redeploy the stack only
```

## One intentional divergence from the shell scripts

`scripts/harden.sh` writes `net.ipv4.ip_forward = 0`. Docker enables IP forwarding
when the daemon starts, but a file in `/etc/sysctl.d/` re-disables it on every
boot — after which Docker bridge networking stops routing and the stack fails to
come back up. The `hardening` role sets it to `1` and leaves the firewalls to do
the filtering. Worth fixing in the shell script too.
